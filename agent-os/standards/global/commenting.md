## Code commenting best practices

- **Self-Documenting Code**: Write code that explains itself through clear structure and naming
- **KDoc on new functions**: Always add KDoc to new functions explaining what the function does and why. Document non-obvious classes and model fields too.
- **Minimal, helpful comments**: Add concise, minimal comments to explain large or non-obvious sections of logic. Don't narrate self-evident code.
- **Don't comment changes or fixes**: Do not leave comments about recent or temporary changes or fixes. Comments should be evergreen and relevant far into the future.
